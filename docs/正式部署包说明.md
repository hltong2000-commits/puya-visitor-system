# 正式部署包说明

## 包含内容

发布包包含 Node.js HTTP 服务、前端静态资源、PostgreSQL 建表脚本、Docker 配置和 `.env.example`。发布包不包含真实密钥、CloudBase API Key、SQLite 数据文件或 `node_modules`。

## 生成发布包

在项目根目录执行：

```powershell
./scripts/package-release.ps1
```

默认生成 `dist/puya-visitor-system-release.zip`。

## 直接部署 Node.js

1. 解压发布包并执行 `npm ci --omit=dev`。
2. 复制 `.env.example` 为平台环境变量，至少设置 `NODE_ENV=production`、`ADMIN_PASSWORD` 以及 PostgreSQL 连接配置（`DATABASE_URL`，或 `PGHOST`、`PGDATABASE`、`PGUSER`、`PGPASSWORD`）。
3. 先在目标 PostgreSQL 数据库执行 `cloudbase/schema.sql`。
4. 使用 `npm start` 启动，平台健康检查设置为 `/api/health`。
5. 通过 HTTPS 反向代理发布根路径和 `/admin`，再生成指向根路径的固定二维码。

## 使用 Docker

```powershell
docker build -t puya-visitor-system .
docker run --rm -p 3000:3000 `
  -e NODE_ENV=production `
  -e ADMIN_PASSWORD="替换为强密码" `
  -e DATABASE_URL="postgresql://用户名:密码@主机:5432/数据库?sslmode=require" `
  puya-visitor-system
```

生产环境必须使用持久化 PostgreSQL，不能使用容器文件系统中的 SQLite。

## CloudBase 部署

CloudBase 环境继续使用仓库根目录的 `cloudbaserc.json` 和 `npx --package @cloudbase/cli@3.8.1 tcb deploy`。发布包适合其他 Node.js、容器或托管平台，不要求目标平台具备 CloudBase CLI。

## 上线检查

- `/api/health` 返回 `ok: true`，并显示目标数据库类型。
- 手机提交登记后显示本次登记摘要。
- `/admin` 登录、查询和导出正常。
- HTTPS 域名稳定后再生成固定二维码。
- 真实密钥只通过平台环境变量注入，不写入压缩包或 Git。
