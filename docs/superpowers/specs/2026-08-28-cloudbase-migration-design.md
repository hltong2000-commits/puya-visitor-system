# 访客系统迁移腾讯 CloudBase 设计

## 目标

将现有普冉半导体访客系统从 Vercel + Neon 迁移到腾讯 CloudBase 免费环境，使访客能够在国内通过微信扫描固定二维码完成登记。CloudBase 使用全新空数据库，不迁移 Neon 测试数据。

本次同时调整登记完成体验：数据库写入成功后，页面显示本次登记的完整摘要，方便访客核对。登记成功即完成流程，不增加前台或员工审核。

## 范围

本次包含：

- 访客登记页、后台管理页和静态资源迁入 CloudBase 静态托管。
- `/api/*` 接口迁入一个 Node.js HTTP 云函数。
- 生产数据库切换为 CloudBase PostgreSQL。
- 保留本机 SQLite 开发模式。
- 增加登记成功摘要。
- 生成指向最终 CloudBase HTTPS 地址的固定二维码。
- 更新 README 和 Obsidian 知识库中的部署、架构、流程与验收说明。

本次不包含：

- Neon 历史数据迁移。
- 员工审批、前台确认、短信通知、门禁和企业微信集成。
- 多管理员、权限中心或新的数据分析功能。
- 删除 Vercel 项目、Neon 数据库或其他云端资源。

## 方案选择

采用“CloudBase 静态托管 + 单个 HTTP 云函数 + CloudBase PostgreSQL”。页面和静态资源由 CDN 提供，API 请求通过同一公网 HTTPS 域名下的 `/api/*` 路由进入云函数。

未选择的方案：

- 全部内容由单个 HTTP 云函数提供：代码调整较少，但静态页面也会消耗函数调用，并增加冷启动影响。
- CloudBase 云托管容器：与现有常驻 Node 服务接近，但本次免费额度和资源成本不如静态托管加云函数明确。

## 系统架构

```text
微信扫码
   |
   v
CloudBase 公网 HTTPS 域名
   |-- /                 访客登记页
   |-- /admin            后台管理页
   |-- /*.js、/*.css     JavaScript 和 CSS
   |-- /assets/*         LOGO、背景图和二维码
   `-- /api/*            HTTP 网关
                              |
                              v
                       Node.js HTTP 云函数
                              |
                              v
                       CloudBase PostgreSQL
```

页面与 API 保持同源，避免微信内置浏览器中的跨域限制，也使后台安全 Cookie 可以继续使用。公开二维码只指向 `/`；后台仍通过 `/admin` 访问。

## 组件职责

### 静态托管

直接发布现有 `public/` 内容，承载登记页、后台页、脚本、样式和图片。现有 HTML 中的 `/static/*.js` 和 `/static/styles.css` 调整为与 `public/` 实际文件结构一致的根路径；本地 Node 服务同步支持这些静态文件路径。后台入口使用 `public/admin/index.html`，静态托管通过目录默认页支持 `/admin`。`/api/*` 由 HTTP 网关转发至云函数。前端继续通过相对路径访问 `/api/*`，不在代码中固化云函数域名。

### HTTP 云函数

复用现有服务端校验、鉴权、审计和重复提交检查。云函数只承担 API 请求，使用声明中已验证的 Node.js 20 运行时，并监听平台要求的端口。服务端不再向生产数据库适配器传递 SQL 字符串，而是调用明确的业务数据方法。

### 数据库适配

生产环境使用 CloudBase 官方 Node SDK 的 `rdb()` 结构化接口访问 PostgreSQL，不开启数据库公网地址，不重置数据库密码，也不在 HTTP 云函数内使用 `PG*` 直连参数。HTTP 云函数使用 `CLOUDBASE_APIKEY` 显式鉴权；该服务端 API Key 只保存在本地忽略文件和 CloudBase 函数环境变量中，不写入 Git、日志或文档。

数据库边界改为明确的业务方法，覆盖管理员初始化与查询、访客重复检查与写入、后台筛选与计数、详情、状态更新和审计日志。SQLite 适配器继续用参数化 SQL 实现这些方法；CloudBase 适配器使用 `select`、`insert`、`update`、`eq`、`gte`、`lt`、`or`、`order` 和 `range` 等 SDK 方法。两个适配器向 `server.js` 提供相同接口，业务路由不感知存储实现。

CloudBase 使用空库，不导入 Neon 测试数据。`visitors`、`admin_users` 和 `audit_logs` 的建表与索引 SQL 在部署前通过 CloudBase CLI 执行一次；运行时 `init()` 只验证数据访问并初始化管理员记录，不在每个函数实例启动时执行 DDL。

非生产环境默认使用本机 SQLite。生产环境缺少 `TCB_ENV_ID` 或 `CLOUDBASE_APIKEY` 时直接失败，不能回退到云函数临时文件系统中的 SQLite。现有 `DATABASE_URL` 和 `PG*` 配置仅作为 Vercel + Neon 短期回退路径，不注入 CloudBase 函数。

## 登记数据流

1. 访客填写姓名、手机号、公司、被访人、来访事由、同行人数和车牌号。
2. 前端向 `POST /api/visitors` 提交 JSON。
3. 云函数执行字段校验和十分钟内同手机号重复检查。
4. 校验通过后写入 PostgreSQL。
5. 只有写入成功后，接口才返回 `201`、成功状态和数据库实际保存的登记摘要。
6. 页面清空表单并切换到成功状态，展示本次登记信息。

成功摘要包含：

- 登记时间
- 姓名
- 完整手机号
- 公司
- 被访人
- 来访事由
- 同行人数
- 车牌号；未填写时显示“未填写”

成功摘要不包含数据库编号、数据来源和内部状态。摘要只存在于当前页面状态，刷新后消失，不新增公开历史查询接口。前端使用文本节点渲染用户数据，不拼接未转义 HTML。

现有“提交后联系前台”和“登记成功，请联系前台”的文字改为无需人工确认的完成提示。

## 后台数据流

后台保留现有功能和接口契约：

- 管理员账号密码登录。
- 按日期和关键词查询。
- 查看完整登记详情。
- 导出 CSV。
- 软隐藏记录。
- 记录登录和状态变更审计日志。

管理员密码通过 `ADMIN_PASSWORD` 注入云函数环境，不写入仓库。生产 Cookie 使用 `Secure`、`HttpOnly` 和 `SameSite=Lax`；固定的环境变量确保不同函数实例可以验证同一会话签名。

## 异常处理

- 字段校验失败：返回 `400` 和字段级错误，页面保留已填写内容。
- 十分钟内重复登记：返回 `409`，由访客明确确认后再次提交。
- 重复点击：请求进行期间禁用提交按钮。
- 网络错误：保留表单内容并提示“网络异常，请重试”。
- 数据库错误：返回通用失败提示，不泄露连接参数或 SQL；页面不得显示成功状态。
- 未登录后台请求：保持返回 `401`。
- 缺少必要生产环境变量：云函数启动或健康检查明确失败，不回退到云端临时文件数据库。
- 健康检查：`/api/health` 只返回服务状态和数据库类型，不返回主机、账号、密码或连接串。

现有进程内限流仅作为单实例保护。CloudBase Serverless 可能同时存在多个实例，因此部署时还需使用 HTTP 网关可用的访问频率限制；不能把内存计数器当作全局限流。

## 固定二维码

二维码只在最终 CloudBase 公网 HTTPS 地址通过浏览器和微信真机验证后生成。二维码内容为登记首页完整地址，不包含后台路径、临时隧道地址或预览部署地址。

更新后的二维码替换 `public/assets/visitor-registration-qr.png`。在最终地址稳定前不打印或对外发布，避免域名变化造成二维码失效。

## 验证与验收

### 自动验证

- 运行现有 Node.js 测试，确认本机 SQLite 和原有接口行为没有回归。
- 增加成功提交测试，验证 `201` 响应包含实际保存的登记摘要。
- 增加失败测试，确认无效字段和数据库写入失败不会返回成功摘要。
- 验证后台登录、查询、详情、软隐藏和 CSV 导出保持正常。
- 使用可注入的伪 `rdb()` 客户端验证 CloudBase 适配器的结构化查询、计数、分页、写入、更新和错误传播，测试不依赖真实 API Key。

### 本机验证

- 使用 SQLite 启动服务并完成一条登记。
- 确认成功摘要与提交内容一致，登记时间可读，空车牌显示“未填写”。
- 确认刷新页面后摘要消失，不能通过公开接口读取历史记录。
- 在窄屏手机视口检查页面无横向滚动、文本遮挡和按钮溢出。

### CloudBase 联调

- `/api/health` 返回 PostgreSQL 状态正常。
- 微信扫描固定二维码可以打开登记页。
- 微信内完成正常登记，成功摘要显示完整。
- 后台查询到与摘要一致的数据库记录。
- 验证无效手机号、缺失字段、重复提交和网络错误提示。
- 验证后台登录、筛选、详情、隐藏和 CSV 导出。

## 上线与回退

上线顺序：

1. 创建 CloudBase 空 PostgreSQL 数据库。
2. 用 CloudBase CLI 执行建表与索引 SQL。
3. 创建服务端 API Key，并将 `TCB_ENV_ID`、`CLOUDBASE_APIKEY` 和 `ADMIN_PASSWORD` 注入函数环境。
4. 部署 HTTP 云函数、静态资源和同源路由。
5. 完成健康检查和浏览器联调。
6. 使用微信进行真机登记和后台查询确认。
7. 确认最终公网地址后生成并替换固定二维码。
8. 更新 README 和 Obsidian 知识库。
9. 完成全部验证后，将相关改动一次性提交并推送 GitHub `main`。

迁移验证期间保留现有 Vercel 配置和部署作为短期回退，但 CloudBase 不读取 Neon 数据。删除或停用 Vercel、Neon 等外部资源需要用户另行明确授权。

## 成功标准

- 国内微信可通过固定二维码访问登记页。
- 有效登记写入 CloudBase PostgreSQL 后才显示成功。
- 成功页面显示本次完整登记摘要，无需前台确认。
- 后台能够查到内容一致的记录，并保留既有管理能力。
- 本机 SQLite 开发模式和现有安全校验保持可用。
- 仓库中不包含管理员密码、CloudBase API Key、数据库密码或完整连接串。
