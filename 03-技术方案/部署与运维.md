# 部署与运维

[[00-MOC/访客系统总览|返回总览]]

## 最小部署

- 一台公司服务器或国内云主机。
- 一个企业域名或内网域名，启用 HTTPS。
- Web 服务以非 root 用户运行。
- 数据库文件和备份目录与静态资源分离。

## 日常运维

- 每日自动备份数据库，至少保留最近 7 个备份版本。
- 定期验证备份可恢复，不只检查文件是否存在。
- 监控接口错误率、响应时间、磁盘空间和备份结果。
- 记录应用版本、配置变更和管理员操作。
- 二维码内容保持稳定，切换域名时使用重定向或重新制作二维码。

## 本地开发

本项目本机使用 Node.js 内置 SQLite；云端 PostgreSQL 模式依赖 `pg`。在项目根目录设置 `ADMIN_PASSWORD` 后执行 `npm start`。登记页为 `/`，后台为 `/admin`。生产环境必须设置管理员密码，不应使用开发默认值。前端视觉样式集中在 `public/styles.css`，LOGO 位于 `public/assets/puya-logo.png`。

## Vercel + Supabase/Neon 试用

将代码推送到 GitHub 后，在 Vercel 导入仓库；在 Supabase 或 Neon 创建 PostgreSQL 数据库，将连接串填入 `DATABASE_URL`。Vercel 入口由 `vercel.json` 指向 `api/index.js`。部署完成后先检查 `/api/health`，确认返回 `database: postgres`，再用公网 HTTPS 地址生成二维码。Vercel 函数使用无状态会话，不能依赖本地文件或内存保存业务数据。

## 本地开发

本项目无第三方运行依赖。在项目根目录设置 `ADMIN_PASSWORD` 后执行 `npm start`。登记页为 `/`，后台为 `/admin`。生产环境必须设置管理员密码，不应使用开发默认值。

## 故障处置

提交失败：前台保留纸质应急登记表；系统恢复后补录并标记来源。数据库异常：暂停后台写入，先保护现场数据和备份，再恢复服务。
