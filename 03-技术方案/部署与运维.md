# 部署与运维

[[00-MOC/访客系统总览|返回总览]]

## CloudBase 目标部署

目标拓扑为 CloudBase 静态托管、同源 `/api/*` 网关、单个 Node.js HTTP 云函数和 CloudBase PostgreSQL。公开二维码指向静态托管的登记首页，后台使用同一 HTTPS 域名下的 `/admin`。当前尚未完成 CloudBase 公网部署，最终 URL 和验证日期只能在浏览器及微信真机联调成功后记录。

CloudBase 使用全新空数据库，不导入 Neon 测试记录。生产函数通过 SDK `rdb()` 访问 PostgreSQL；缺少 `TCB_ENV_ID` 或 `CLOUDBASE_APIKEY` 时必须启动失败，不得回退到云函数临时文件系统中的 SQLite。

## 环境变量与密钥

| 分类 | 变量 |
| --- | --- |
| CloudBase 项目 | `TCB_ENV_ID`；地域在 `cloudbaserc.json` 固定为 `ap-shanghai` |
| 管理员 | `ADMIN_PASSWORD` |
| CloudBase 函数 | `TCB_ENV_ID`、`CLOUDBASE_APIKEY`、`ADMIN_PASSWORD`；SDK `rdb()` 访问 PostgreSQL |

真实值只保存在被 Git 忽略的 `.env.local` 或 CloudBase 环境变量设置中，不得写入代码、文档、提交记录或 GitHub。`DATABASE_URL` 仅用于旧 Vercel + Neon 环境的兼容回退。

## 验证与部署

加载本地私密环境变量后，先验证声明，再执行部署：

```powershell
$env:TCB_ENV_ID = 'puya-visitor-system-d8bjd061ec19'
npx --package @cloudbase/cli@3.8.1 tcb validate
npx --package @cloudbase/cli@3.8.1 tcb deploy
```

部署后按顺序验收：

1. `/api/health` 返回服务正常且数据库类型为 `postgres`。
2. 访客提交有效登记，页面显示与数据库实际保存内容一致的 8 项摘要。
3. 管理员登录后台，能够查询到同一条记录并正常查看详情、导出和隐藏。
4. 无效字段、重复登记和数据库失败不会显示成功摘要。
5. 微信扫描最终固定二维码可以打开页面并完成登记。

完成以上检查后，才把最终登记页 URL、`/admin`、`/api/health` 和验证日期写入知识库，并重新生成 `public/assets/visitor-registration-qr.png`。在此之前不得使用预览地址或临时隧道制作正式二维码。

## 日常运维

- 按 CloudBase 能力配置数据库备份或定期导出，并验证数据能够恢复。
- 定期验证备份可恢复，不只检查文件是否存在。
- 监控接口错误率、响应时间、数据库连接、资源点和流量配额。
- 记录应用版本、配置变更和管理员操作。
- 二维码内容保持稳定，切换域名时使用重定向或重新制作二维码。
- 免费环境需要定期续期；同时监控函数、数据库、存储和 CDN 用量，不能将其视为永久无限额资源。

## 本地开发

本项目本机使用 Node.js 内置 SQLite；云端 PostgreSQL 模式依赖 `pg`。在项目根目录设置 `ADMIN_PASSWORD` 后执行 `npm start`。登记页为 `/`，后台为 `/admin`。生产环境必须设置管理员密码，不应使用开发默认值。前端视觉样式集中在 `public/styles.css`，透明 LOGO 位于 `public/assets/puya-logo-transparent.png`。

## 故障处置

提交失败：前台保留纸质应急登记表；系统恢复后补录并标记来源。数据库异常：暂停后台写入，先保护现场数据和备份，再恢复服务。
