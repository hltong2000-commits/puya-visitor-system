# 系统架构

[[00-MOC/访客系统总览|返回总览]]

## 终端与目标架构

使用者终端为手机浏览器；二维码只承担打开 H5 地址的入口作用，不承载访客个人信息。

```text
微信/手机浏览器
      |
      v
CloudBase 静态托管
      |
      +-- / 和 /admin
      |
      `-- 同源 /api 网关 --> Node.js HTTP 云函数 --> CloudBase PostgreSQL
```

前台、后台与 API 使用同一 CloudBase 公网 HTTPS 域名。`public/` 由静态托管直接提供，`/api/*` 经同源网关进入单个 HTTP 云函数，避免微信内置浏览器的跨域问题，并继续支持后台安全 Cookie。云函数通过 `TCB_ENV_ID` 和 `CLOUDBASE_APIKEY` 初始化 SDK，调用 `rdb()` 访问 CloudBase PostgreSQL；云端不使用 SQLite 作为持久化存储。

本机开发继续通过 Node HTTP 服务和 SQLite 运行。已验证的 Vercel + Neon 环境仅在迁移期间作为临时回退，`DATABASE_URL` 只保留兼容用途，不是 CloudBase 的目标配置，也不向 CloudBase 迁移 Neon 测试数据。

## 组件职责

- CloudBase 静态托管：提供 H5、后台页面、脚本、样式和品牌图片。
- 同源 API 网关：将 `/api/*` 转发至 HTTP 云函数，并承担平台可用的访问频率限制。
- Node.js HTTP 云函数：服务端校验、限流、防重复、写入、查询、导出和鉴权。
- CloudBase PostgreSQL：保存访客记录、后台账号和操作日志。
- 本机 SQLite：仅用于本地开发和自动测试。

## 关键取舍

不引入微服务、消息队列和复杂权限中心。当前访问量和流程复杂度不足以支撑这些组件；未来若增加审批、短信或门禁，再按边界扩展。
