# 系统架构

[[00-MOC/访客系统总览|返回总览]]

## 终端与推荐架构

使用者终端为手机浏览器；二维码只承担打开 H5 地址的入口作用，不承载访客个人信息。

```text
手机浏览器 --HTTPS--> H5 静态页面 --HTTPS/JSON--> Web API --参数化 SQL--> 数据库
                                                  |
                                                  +--> 管理后台
```

首版使用单体 Web 服务即可：同一域名下提供 H5、后台和 API。本机通过 Node HTTP 服务运行；Vercel 通过 `api/index.js` 运行 Serverless 入口。应用通过 `DATABASE_URL` 自动选择数据库：本机未配置时使用 SQLite，Vercel/Supabase 或 Neon 部署时使用 PostgreSQL。云端不使用 SQLite 作为长期数据存储。

## 组件职责

- H5：表单展示、客户端校验、提交状态和成功页。
- Web API：服务端校验、限流、写入、查询、导出和鉴权。
- 数据库：访客记录、后台账号、操作日志。
- 反向代理：HTTPS、静态资源缓存和基础安全头。

## 关键取舍

不引入微服务、消息队列和复杂权限中心。当前访问量和流程复杂度不足以支撑这些组件；未来若增加审批、短信或门禁，再按边界扩展。
